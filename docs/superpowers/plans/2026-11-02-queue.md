# Queue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Queue module (`modules/requests`) where things that need you are filed once and reviewed once (Make task, Handled, Not for me, Reopen), plus the Core piece it needs: an operation may call another module's operation in the caller's transaction.

**Architecture:** `calls` is declared on the operation description in `@dlh/core`. `@dlh/server` checks the calls at registration and gives the mutation's scoped writer a `call` method that runs the callee through its own input schema and effects, in the same transaction, with its created items added to the caller's undo token. `modules/requests` owns the `requests` table and its migrations. Its operations are tRPC endpoints, ⌘K actions and AI actions in one place, like Tasks. `makeTask` creates its task through `w.call(taskOps.create, …)`, never through Tasks' table. The screens are built from `@dlh/ui` patterns already used by Tasks.

**Tech Stack:** TypeScript, Zod 4, tRPC 11, Drizzle + Postgres, React 19 + TanStack Query/Router, `@dlh/ui` (React Aria), Vitest, Playwright.

**Spec:** `docs/specs/requests.md` (Queue). Read with `docs/specs/tasks.md` (operations, migrations, Undo) and `docs/superpowers/plans/2026-11-02-tasks.md` (what each Core piece is called).

**Decisions made while planning**

- **Called queries are allowed.** The spec's Operation calls section says a callee may be "a mutation or a query", and the Agent hub spec relies on that. The Testing line "registration refuses … a query" is stale. Task 1 removes it from the spec. A called query runs on the caller's transaction (`deps` with `db` set to `w.tx`), so it sees the caller's writes.
- **A callee's own undo record is dropped.** The caller's token holds the caller's record, plus every item created by the caller or its callees. Core soft-deletes those first, and then the caller's `undo` reverses everything else, including any non-create effects of its callees. `tasks.create`'s undo is already a no-op (`undoRecord: z.null()`), so Make task needs nothing more.
- **`w.call` returns `unknown`.** Descriptions don't carry result types, so the caller parses the result. `makeTask` uses Core's `item` schema.
- **Tasks gains a subpath export `@dlh/module-tasks/operations`** (`./src/operations.ts`). Requests imports `taskOps` from it, so server code never imports Tasks' manifest or screens.
- **The outcome link is tagged.** The `relates` link written by `resolve`/`makeTask` has `context: "outcome"`. `reopen` and Detail look only for that link. A `relates` link you added by hand to the same task is never removed. If the link already existed (`addLink` returns it unchanged), `reopen` leaves it alone.
- **Filing idempotently uses an advisory lock.** `file` with an `externalId` first takes `pg_advisory_xact_lock(hashtext(source || ':' || external_id))`, then reads. The unique index is the backstop. A pair that matches a soft-deleted request returns that request with `existing: true` and writes nothing, so a source can't refile what you deleted.
- **`source` defaults to `ai` when it's left out.** ⌘K's `toInput` and the screens always send `"manual"`. AI fills the input from the model, so a filing with no source is an AI filing. Server sources pass theirs explicitly.
- **⌘K shows one row for `resolve`.** The row is "Resolve request", and its form has an outcome choice of Handled or Not for me. `prefill` sets the outcome from the typed text ("handled", "done with this" → `handled`; "not for me", "ignore" → `not_for_me`). Core gives one palette row per operation, and this avoids a Core change.
- **The nav count is a module component.** `ModuleManifest.nav.badge?: ComponentType` renders inside the dock item through a new `DockItem.badge?: ReactNode`. Queue's badge reads `requests.open` and renders nothing at 0.
- **The Home widget is declared provisionally.** `ModuleManifest.homeWidgets?: { id: string; label: string; component: ComponentType }[]` exists so Queue can declare `needsYou`. Nothing renders it until Home, and the Home spec may reshape the type.
- **`--color-type-request` is `#8fd3cf` (teal) for now.** It replaces the open question until the design pass picks the final value.
- **`makeTask` on a resolved request is `CONFLICT`,** like `resolve` with a different outcome.

## Global Constraints

- Module id `requests`, item type `request`, nav label "Queue", path `/queue`, shortcut `g q`, icon `Inbox`.
- `source` is one of `manual`, `ai`, `slack`, `agent`. `outcome` is one of `task`, `handled`, `not_for_me`. `outcome` and `resolved_at` are both null or both set. `external_id` is null when `source = 'manual'`.
- `actions`: at most 3 `{ label, operation, input }`. Each `operation` is a registered mutation whose `calls` include `requests.resolve`.
- Calls are one level deep. A caller may not call itself and must list the callee in `calls`.
- `open` lists open requests, oldest `received_at` first. `resolved` covers the last 30 days, newest `resolved_at` first, 50 per page.
- Every write calls `updateItem` (so `updated_at` moves and a change is published). Modules never import `@dlh/db`, and module JSX uses layout classes only.
- Sync: a change on another device shows within 2 seconds.
- AI: at least 8 phrasings per Queue AI action (`requests.file`, `.resolve`, `.makeTask`, `.open`). The keyword interpreter must score 90% or better on core + tasks + requests phrasings together.
- Copy (verbatim): "Nothing waiting on you" · "Nothing resolved yet" · "It changed elsewhere; try again" · "Task deleted" · "You" · "File a request" · "Make task" · "Handled" · "Not for me" · "Reopen" · "Open in Slack".

## Review Focus

1. **Handled pressed twice, or on two devices.** The second call with the same outcome is a no-op that returns the request unchanged, even with a stale `expectedUpdatedAt`, and it writes nothing. A different outcome is `CONFLICT`. Test: Task 3 `resolve twice with a stale version is a no-op`.
2. **Undo of Make task after the new task was edited.** The task is still soft-deleted and the request reopens. If the request itself changed since, the result is `CONFLICT` "Changed since" and nothing is reverted. Test: Task 3 `makeTask undo after the task was edited still removes it`.
3. **Reopen when you had linked the same task by hand.** Only the `context: "outcome"` link goes, and your link stays. Test: Task 3 `reopen keeps a link the person added`.
4. **"remind me to…" in ⌘K or AI.** It must still reach `tasks.create` when a date or a to-do is meant, and reach `requests.file` for "remind me to look at…". Tasks' phrasings stay in the combined gate. Test: Task 5 `keywordInterpreter scores ≥ 0.9 on core + tasks + requests phrasings`.
5. **A source refiling something you deleted.** `file` with the pair of a soft-deleted request returns it (`existing: true`) and creates nothing. The same `externalId` under a different `source` is a separate request. Test: Task 3 `file after delete returns the deleted request and writes nothing`.
